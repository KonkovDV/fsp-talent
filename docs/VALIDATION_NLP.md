# Валидация разбора резюме и вакансий по полям

Команда: `cd backend && python -m app.validation.nlp` (зерно 2026, 60 резюме на шаблон, 24 вакансии; ~5 с на CPU, результат детерминирован: два прогона дают одинаковый вывод). Тест: `tests/unit/test_validation_nlp.py`.

Покрывает ТЗ 2.1 (загрузка PDF с автораспознаванием), 3.2 (NLP) и 3.4 (валидация). Измеряется только режим правил: модель (LLM) требует ключа и недетерминирована — **с LLM точность не измерена**.

## Метод
- **Резюме.** Синтетические люди с известной истиной (ФИО, почта, телефон, Telegram, стаж, специализация, грейд, навыки) рендерятся в PDF двумя шаблонами: двухколоночный экспорт в стиле hh.ru (подписи слева, значения справа) и свободный текст. Дальше — путь продукта: `extract_pdf_text` → `extract_resume_fields` + `extract_skills`. В 40 % резюме часть навыков записана разговорными вариантами (Postgres, k8s, JS, sklearn, Golang, GitLab CI, Vue). В свободном шаблоне в 25 % случаев Telegram дан ссылкой `t.me/…`, а ещё в 25 % стаж записан годом начала («в разработке с 2021 года») — правила такие формы не разбирают, и это видно в цифрах.
- **Вакансии.** 24 текста разных стилей, написаны вручную, с эталоном полей (`backend/app/validation/resources/nlp_vacancies_gold.json`) → `draft_need`.
- **Метрики.** Скалярные поля — точное совпадение (пропуск = ошибка; эталонный `null` верен, только если ничего не найдено). Навыки — P/R/F1 по множеству, среднее по документам (как в CoNLL-2003, arXiv:cs/0306050).

## Ограничения и найденные ошибки
- Шаблоны резюме синтетические и чистые; на реальных PDF (сканы, многоколоночные вёрстки, таблицы) точность ниже. Сканы без текстового слоя не распознаются (OCR нет).
- Стаж, записанный годом начала, и Telegram ссылкой `t.me/…` правила не извлекают — их кандидат вводит вручную при подтверждении полей.
- Вилка: не разбираются «350–450k», «120–160 тыс.» (диапазон с сокращением после второго числа) — сокращение применяется только ко второму числу.
- Город: склонённые формы («в Казани», «в Москве», «в Уфе») не находятся — поиск по точному названию.
- Специализация: «Go-разработчик» без слова «бэкенд» и «робототехник» не распознаются.
