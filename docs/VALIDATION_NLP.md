# Валидация разбора резюме и вакансий по полям

Команда: `cd backend && python -m app.validation.nlp` (зерно 2026, 60 персон × 3 шаблона резюме, 24 + 30 вакансий; ~9 с на CPU, результат детерминирован: два прогона дают одинаковый вывод). Тест: `tests/unit/test_validation_nlp.py`.

Покрывает ТЗ 2.1 (загрузка PDF с автораспознаванием), 3.2 (NLP) и 3.4 (валидация). Измеряется только режим правил: модель (LLM) требует ключа и недетерминирована — **с LLM точность не измерена**.

## Метод
- **Резюме.** Генератор создаёт персону с известным ответом: ФИО (в трёх порядках слов, 40 % женских), почта, телефон в четырёх записях, Telegram у 65 %, стаж по грейду, одна из 10 специализаций, грейд (у 12 % грейд в заголовке не указан), 4–7 навыков из пула специализации. Каждая персона записывается тремя собственными шаблонами: карточка профиля со строками «Подпись: значение», сопроводительное письмо обычными фразами и резюме по блокам «КОНТАКТЫ / КАРЬЕРА / СТЕК». Дальше путь продукта: PDF → `extract_pdf_text` → `extract_resume_fields` + `extract_skills`. В 30 % случаев навык записан разговорным вариантом (постгрес, кубер, TS, питон, JS, golang, torch, GitHub Actions, dart). В письме нарочно есть формы, которые правила не разбирают: в 20 % стаж дан годом начала («пишу код за деньги с 2021 года»), в 20 % Telegram дан ссылкой `https://t.me/…`. Это видно в цифрах.
- **Вакансии.** 24 текста разных стилей, написаны вручную, с эталоном полей (`backend/app/validation/resources/nlp_vacancies_gold.json`) → `draft_need`.
- **Отложенный набор вакансий.** Ещё 30 текстов с эталоном (`nlp_vacancies_holdout.json`) написаны до разбора ошибок и до правил вилки, падежей городов и стека в заголовке; эталон после этого не менялся. Цифры по нему показывают, переносятся ли правила на новые тексты.
- **Метрики.** Скалярные поля — точное совпадение (пропуск = ошибка; эталонный `null` верен, только если ничего не найдено) и P/R/F1 по полю: P = верные / найденные, R = верные / заданные в эталоне. Вилка — одно поле, верна только при обеих совпавших границах. Навыки — P/R/F1 по множеству, среднее по документам (как в CoNLL-2003, arXiv:cs/0306050).

**Правила разбора вакансии** (`backend/app/services/need_draft.py`, `cities.py`):
- Вилка: диапазон «от A до B», «A–B», «A тыс. – B тыс.», «A ₽ – B ₽»; единица после второго числа («120–160 тыс.», «350–450k») относится к обеим границам; слова gross/net, «на руки», «до вычета НДФЛ» числа не меняют. Опыт «от 2 до 4 лет», часы работы и проценты премии вилкой не считаются (границы 20 000 – 2 000 000 ₽). Одна граница («до 300 000 ₽», «от 280 000 руб.») записывается в оба поля.
- Город: любой падеж («в Москве», «из Новосибирска», «в Перми», «в Нижнем Новгороде») и обиходные имена (СПб, Питер, Екб, Мск); при нескольких городах — первый упомянутый.
- Специализация: сначала заголовок (слово роли, затем стек: Go/Golang, Java, Python, PHP, C#, Node.js → бэкенд; React, Vue, Angular → фронтенд; Flutter, Swift → мобильная), потом весь текст. Языки нескольких направлений (C++, Rust, Kotlin, JavaScript, TypeScript) специализацию не задают. «Робототехник» → встраиваемые системы (как дисциплина «робототехника» в `DISCIPLINE_ROLE_MAP`). Стажировка без явного грейда → грейд «стажёр».

## Ограничения и найденные ошибки
- Шаблоны резюме синтетические и чистые; на реальных PDF (сканы, многоколоночные вёрстки, таблицы) точность ниже. Сканы без текстового слоя не распознаются (OCR нет).
- Стаж, записанный годом начала, и Telegram ссылкой `https://t.me/…` правила не извлекают — их кандидат вводит вручную при подтверждении полей.
- Оба набора вакансий написаны командой; на потоке реальных вакансий с hh.ru точность не измерялась. Город ищется только среди 15 городов справочника.
- Специализация: «Стажёр-разработчик C#» правило относит к бэкенду (в таксономии навыков C# — бэкенд), эталон набора PR #305 оставляет специализацию пустой; эталон не правился. «Rust-разработчик» и «Разработчик C++ (компьютерное зрение)» специализацию не получают: языки нескольких направлений правило намеренно пропускает.
- Формат: «офис или удалёнка — гибрид» определяется как удалёнка (первым срабатывает слово «удалёнка»).
