# 0007. Удостоверения W3C VC 2.0 с подписью Ed25519

**Контекст.** Подтверждённый грейд и результаты ФСП нужно показать за пределами платформы, а проверяющий не должен зависеть от её базы данных или доступности.

**Решение.** Удостоверение — W3C Verifiable Credentials Data Model 2.0 с Data Integrity `eddsa-jcs-2022`, ключ Ed25519, издатель — платформа (`backend/app/services/vc/issuer.py`). DID издателя и статус удостоверения отдаются открытыми эндпоинтами (`GET /api/v1/public/credentials/{credential_id}/status`, `backend/app/api/v1/public.py`). Когда ФСП начнёт подписывать своим ключом, меняется только блок издателя.

**Альтернативы.** PDF-сертификат или ссылка на страницу — подделывается или требует доступности сайта. JWT-сертификат — проверяется, но не по открытому стандарту для удостоверений. Блокчейн-реестр — инфраструктура без выгоды для проверки одной подписи.

**Последствия.** Проверка подписи не требует обращения к базе. Канонизация — сортировка ключей и компактная запись (совпадает с RFC 8785 для выдаваемых полей без дробных чисел). Ключ подписи хранится в томе `vc_keys`: без него выданные подписи не проверить, поэтому том входит в резервную копию.
