# 0009. Argon2id и короткий JWT с эпохой сессии

**Контекст.** Пароли должны выдерживать офлайн-перебор после утечки базы. Сессия должна закрываться сразу при смене пароля, блокировке или удалении, но без запроса в хранилище сессий на каждый вызов API.

**Решение.** Новые пароли хэшируются Argon2id с параметрами OWASP, старые хэши bcrypt проверяются, и хэш со старыми параметрами пересчитывается при входе (`password_needs_rehash`) (`backend/app/core/security.py`). Access-токен — JWT на 60 минут (`ACCESS_TOKEN_EXPIRE_MINUTES`), refresh — httpOnly-cookie с поколениями. В токене эпоха аккаунта; каждый запрос сверяет её с базой (`backend/app/api/deps.py`), поэтому смена и сброс пароля, повтор старого refresh, закрытие входа модератором и удаление аккаунта гасят все токены сразу.

**Альтернативы.** bcrypt — без защиты памятью от перебора на GPU. Сессии в Redis — запрос в хранилище на каждый вызов и ещё одна точка отказа. Длинный JWT без проверки эпохи — нельзя закрыть сессию до истечения.

**Последствия.** Обычный выход гасит refresh-поколение и токен в браузере; украденный access-токен после выхода живёт до своего срока, если не сменить пароль. Чтение аккаунта на запрос уже нужно для проверки удаления и блокировки, поэтому эпоха не добавляет запросов.
