# ФСП Талант: описание решения

Документ отвечает на раздел 3.4 технического задания спецтрека. Все цифры получены запуском кода, команды приведены рядом.

## Архитектура

Приложение состоит из трёх слоёв. Интерфейс написан на React, Vite и TypeScript. Сервер — FastAPI, SQLAlchemy и Alembic. Данные хранятся в PostgreSQL 16 с расширениями pgvector и pg_trgm, лимиты запросов — в Redis. Всё собирается в `docker-compose.yml`. Снаружи доступен только nginx на порту 80, API и база слушают localhost.

Права ролей проверяются по токену: кандидат не может искать других кандидатов и рассылать приглашения, работодатель не может менять чужой профиль. Контакты кандидата выдаёт отдельный метод API и только после принятия приглашения или собственного отклика кандидата, при действующем согласии на обработку данных. Каждая выдача записывается в журнал доступа. Отзыв согласия закрывает контакты сразу, через 30 дней задача `purge_withdrawn` стирает идентифицирующие данные. Удаление аккаунта стирает их немедленно (`app/services/privacy.py`).

Каждый шаг найма порождает уведомление второй стороне: запись на сайте и письмо, которое уходит после фиксации транзакции (`app/services/notify.py`).

## Механика тестирования

Единый банк вопросов со временем утекает. Генерация задания нейросетью для каждого кандидата делает сложность несравнимой. Поэтому платформа использует третий путь: параметрические семейства заданий.

Семейство собирает задание по шаблону с новыми параметрами, а правильный ответ вычисляет код. Юнит-тест перезапускает каждый фрагмент в Python, Node.js, Go, Java или SQLite и сверяет ключ. Концептуальных вопросов не больше 30 %.

Тест адаптивный и построен на модели IRT 3PL. Если ответ задания с кодом — целое число, кандидат вводит его сам. Это важно на границе грейда: при выборе из четырёх вариантов угадывание отнимает у задания около 40 % информации. Следующее задание выбирается так, чтобы точнее всего различить уровни вокруг порога заявленного грейда. Тест заканчивается через 8–20 заданий, как только уровень определён. Подтверждённый грейд не понижается, повышение доступно раз в 90 дней, пересдача того же уровня — через 7 дней. Для стажировки есть грейд «стажёр» с порогом на ступень ниже junior.

Описание вакансии меняет доли тем: названные навыки подтягивают свои семейства, остальное берётся из плана специализации (`app/services/vacancy_exam.py`). Рядом с долями показаны цитаты из текста, по которым определён навык. Кнопка «Какой тест получится» показывает работодателю доли тем и три примера заданий без ответа. Кандидат может пройти полный тест по вакансии или одно короткое задание для практики. После теста платформа предлагает практику по самой слабой теме. Практика не меняет грейд и отмечается на анонимной карточке. Код кандидата платформа не запускает: ответы проверяются по заранее вычисленным ключам.

Утечку ключа выдаёт аномальный рост доли верных ответов. Ключ с z ≥ 3,5 уходит в карантин и больше не выдаётся.

На 2000 смоделированных кандидатах (`python -m app.validation.assessment --n 2000 --seed 7`) тест принимает верное решение в 92,7 % случаев, если кандидат дальше 0,5 от границы грейда. Каппа повторной сдачи — 0,48. Те же люди при выборе ответа из четырёх вариантов дают 85,9 % и 0,43: ввод числа заметно повышает точность и устойчивость. Даже если ответы главного семейства знают 30 % кандидатов, точность вдали от границы остаётся около 89 %, а карантин снижает долю ложно сдавших с 16 % до 10 %. Методика и все таблицы: [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md).

## Механика подбора и категоризация

Категория — это специализация из опроса и грейд. Грейд подтверждается тестом по этой специализации. Результаты соревнований в грейд не переводятся: это отдельная ось профиля с методикой `v2.0.0` (процентиль Хазена, лестница разрядов ЕВСК, байесовское сжатие к среднему, ранжирование по нижней границе, вес командного результата `1/√m`).

Работодатель описывает потребность и получает подборку, где у каждого кандидата видны сработавшие факторы. До трёх кандидатов можно сравнить рядом, без имён и контактов. В разборе карточки есть строка «Лучше N % кандидатов категории» — место по результату теста среди подтверждённых профилей той же специализации и грейда; она считается одним запросом.

Попадание в список решает соответствие потребности: навыки, грейд, специализация. Среди кандидатов с одинаковым соответствием выше тот, у кого сильнее тест и протокол ФСП. Кандидат без истории ФСП не штрафуется: эта ось для него просто не учитывается. Заявленный навык весит 0,55 от навыка, подтверждённого тестом.

На двух синтетических наборах подбор обходит поиск по ключевым словам на 0,064 и 0,048 nDCG@10 (`python -m app.validation.matching`). Подробности: [VALIDATION_MATCHING.md](VALIDATION_MATCHING.md).

## Интеграция с реестром ФСП

Интеграция вынесена в адаптер. Для демонстрации работает `MockFSPAdapter` с синтетическими протоколами, `RealFSPAdapter` подключается по спецификации API Федерации без изменений в остальном коде. ФСП ID привязывается в профиле после регистрации по почте и не обязателен.

Удостоверения выдаёт платформа: она подтверждает, что результат получен из системы ФСП. Проверить подпись можно через `GET /api/v1/public/issuer` и `POST /api/v1/public/credentials/verify`.

## API

Спецификация открыта по адресу `http://localhost/docs`. Swagger UI 5 отдаётся с того же адреса, без внешних CDN и встроенных скриптов, поэтому работает при строгой политике безопасности `script-src 'self'`. Ошибки приходят в одном формате с машинным кодом: [API_ERRORS.md](API_ERRORS.md).

## Библиотеки

Версии закреплены в `backend/pyproject.toml` и `frontend/package-lock.json`. Основные: FastAPI, SQLAlchemy 2, Alembic, Pydantic 2, bcrypt, python-jose, React 18, Vite 6, Tailwind. PDF-резюме читает `pypdf`, PDF профиля формирует `fpdf2` с системным шрифтом. Смысловой поиск по эмбеддингам включается настройкой `EMBEDDINGS_MODE=model`.

## Кабинет работодателя и PDF

Работодатель ведёт карточку компании (`/employer/company`): название, ИНН с проверкой контрольной суммы, сайт, описание. Рядом с формой видно, как приглашение будет выглядеть для кандидата. Вакансию можно изменить после публикации. Статус отклика меняется в таблице откликов, и кандидат сразу видит его у себя.

PDF-резюме разбирается и не сохраняется. Навыки из словаря попадают в паспорт сразу: источник, дата подтверждения и вес в подборке. Имя, телефон, Telegram, стаж, заявленный грейд и специализация предлагаются вместе с цитатой из текста и переносятся по кнопке «Применить». Почта, указанная при регистрации, из резюме не меняется. PDF профиля скачивается из кабинета и с публичной страницы, если кандидат дал согласие на её публикацию. Контактов в этом файле нет.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec -u appuser backend python -m seed.generate_seed
```

Сайт: http://localhost. Письма с кодами: http://localhost:8025. Демо-пароль `demo12345`: `fsp001@demo.talent`, `nofsp@demo.talent`, `hr@sibcode.demo`.

Проверки: `cd backend && pytest tests/unit` и `cd frontend && npm run type-check && npm run build`. CI выполняет то же, а также применяет миграции, загружает демо-данные, прогоняет сквозной тест API и повторяет проверку адаптивного теста.
