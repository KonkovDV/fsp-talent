# ФСП Талант: сопроводительное описание решения

Документ закрывает раздел 3.4 технического задания спецтрека. Цифры валидации — из прогонов кода, не из оценок на глаз.

## Функциональная и компонентная архитектура

Монолит с тремя слоями. Frontend — React, Vite, TypeScript. Backend — FastAPI, SQLAlchemy, Alembic. Хранение — PostgreSQL 16 (pgvector, pg_trgm) и Redis для лимитов. Контейнеры: `docker-compose.yml`. Публично снаружи nginx на порту 80; API и база на localhost.

Роли разделены токеном: кандидат не вызывает поиск и приглашения, работодатель не меняет чужой профиль. Контакты отдаёт отдельный эндпоинт и только после принятия приглашения или своего отклика, при действующем согласии на обработку. Событие пишется в журнал доступа. Отзыв согласия закрывает контакты сразу; через 30 дней задача `purge_withdrawn` стирает идентифицирующие поля, удаление аккаунта стирает сразу (`app/services/privacy.py`).

Каждый шаг найма порождает уведомление второй стороне: строку для колокольчика и письмо после коммита транзакции (`app/services/notify.py`).

## Механика тестирования

Единый банк вопросов не используется: он утечёт. Нейросеть не генерирует задание на каждого кандидата: сложность была бы несравнима.

Задание собирает параметрическое семейство. Ответ вычисляется кодом. Юнит-тест перезапускает фрагмент в Python, Node.js, Go, Java или SQLite и сверяет ключ. Концептуальных вопросов не больше 30 %.

Сессия адаптивная (3PL, апостериор на сетке). Если ответ задания с кодом — целое число, кандидат вводит его сам: угадывание одного из четырёх на пороге грейда оставляет заданию около 60 % его информации. Следующее задание выбирается по информации у порога заявленного грейда. Остановка при 8–20 заданиях, когда вероятность уровня уже решена. Грейд не понижается. Повышение не чаще чем раз в 90 дней. Пересдача того же уровня — через 7 дней.

Описание вакансии меняет доли тем: названные навыки подтягивают свои семейства, остальное остаётся планом специализации (`app/services/vacancy_exam.py`). Рядом с долями показываются цитаты из текста, из которых взят навык. Работодатель нажимает «Какой тест получится» и видит доли и три примера без ключа. Кандидат может пройти полный тест по вакансии или одно короткое задание. После экзамена слабая тема ведёт на эту практику. Короткое задание не меняет грейд и отмечается на анонимной карточке. Идея взята у «Контура талантов» (задание из требований роли, цитата требования и добровольная практика по слабой теме); исполнение — наши семейства, без чужого кода и без запуска присланного кандидатом кода.

Утечка ловится по дрейфу решаемости. Ключ с z ≥ 3,5 уходит в карантин и больше не выдаётся.

Процедура и цифры: [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md). На одних и тех же 2000 кандидатах (seed 7) ввод числа даёт 91,7 % верных решений дальше 0,5 от границы грейда против 88,5 %, когда все ответы выбирают из четырёх. Каппа повторной сдачи — 0,51 против 0,42. Утечка у 30 % кандидатов поднимает долю ложно сдавших до 14,7 %; карантин ловит 8 из 28 утёкших ключей.

## Механика подбора и категоризация

Категория — специализация из опроса и грейд. Грейд подтверждает тест по этой специализации. Соревнования в грейд не переводятся: это отдельная ось, скоринг `v2.0.0` (процентиль Хазена, лестница ЕВСК, сжатие к среднему, ранжирование по нижней границе, командный вес `1/√m`).

Работодатель описывает потребность. Подборка объясняется факторами. До трёх кандидатов из этой подборки сравниваются по факторам рядом; имя и контакты в сравнение не попадают. В разборе карточки есть перцентиль внутри категории «специализация × грейд» по вероятности теста: «Лучше N % кандидатов категории …». Он считается одним запросом по подтверждённым профилям этой категории. Соответствие потребности (навыки, грейд, специализация) решает, попадает ли человек в список. Внутри одной сотой этого соответствия выше тот, у кого сильнее тест и протокол ФСП. Нет истории ФСП — ось выбрасывается и не штрафует. Заявленный навык весит 0,55 от навыка, который подтвердил тест.

Цифры: [VALIDATION_MATCHING.md](VALIDATION_MATCHING.md). На двух синтетических наборах скор выше базовой линии по ключевым словам на 0,040 и 0,051 nDCG@10.

## Интеграция с реестром ФСП

API реестра в хакатоне нет. Адаптер `MockFSPAdapter` отдаёт синтетические протоколы; `RealFSPAdapter` ждёт спецификацию. ФСП ID привязывается в профиле после регистрации по почте и не обязателен. Издатель удостоверения — платформа, не Федерация: она подтверждает, что результат получен из системы ФСП. Проверка подписи: `GET /api/v1/public/issuer` и `POST /api/v1/public/credentials/verify`.

## API

Спецификация: `http://localhost/docs` (Swagger UI 5 отдаётся с того же адреса, без CDN и встроенных скриптов, поэтому работает под CSP `script-src 'self'`). Ошибки одного формата с машинным кодом: [API_ERRORS.md](API_ERRORS.md).

## Библиотеки

Версии фиксирует `backend/pyproject.toml` и `frontend/package-lock.json`. Основные: FastAPI, SQLAlchemy 2, Alembic, Pydantic v2, bcrypt, python-jose, React 18, Vite 6, Tailwind. PDF резюме читает `pypdf`, PDF профиля пишет `fpdf2` (системный шрифт, без WeasyPrint). Эмбеддинги выключены (`EMBEDDINGS_MODE=off`), пока не подключена модель.

## Кабинет работодателя и PDF

Работодатель ведёт карточку компании (`/employer/company`): название, ИНН с проверкой контрольной суммы, сайт, описание. Вакансию можно изменить. Статус отклика меняется в таблице откликов, кандидат видит его у себя.

PDF-резюме разбирается и не сохраняется. Навыки из словаря попадают в список сразу. Имя, телефон, Telegram, стаж, заявленный грейд и специализация предлагаются вместе с цитатой из текста и переносятся в профиль только по кнопке «Применить». Входная почта из резюме не меняется, мягкие навыки в поиск не входят. PDF-профиль скачивается из кабинета и с публичной страницы, если на неё есть согласие. Контактов в файле нет.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec -u appuser backend python -m seed.generate_seed
```

Сайт: http://localhost. Письма с кодами: http://localhost:8025. Демо-пароль `demo12345`: `fsp001@demo.talent`, `nofsp@demo.talent`, `hr@sibcode.demo`.

Проверки: `cd backend && pytest tests/unit` и `cd frontend && npm run type-check && npm run build`. CI делает то же плюс миграции и дымовой тест.
