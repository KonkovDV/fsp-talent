**команда Дмитрия Конькова** · [стенд](https://89-124-65-102.sslip.io) · [репозиторий](https://github.com/KonkovDV/fsp-talent)

ТЗ описывает работающий MVP обратного найма. Мы сделали платформу, готовую к пилоту: адаптивный тест, который нельзя выучить, объяснимый подбор, подписанные удостоверения, защита персональных данных и правовой пакет. Каждая строка ниже ведёт к коду, тесту или документу и проверяется за минуту.

## Проверка за 3 минуты

**Демо-входы и три клика до результата.**
Жюри входит готовыми аккаунтами, а на `/jury` в «Режиме эксперта» видит адаптивный тест по шагам без входа.
Доказательство: [README](../README.md#проверьте-нас-за-3-минуты).

**Одна команда пересчитывает главные цифры.**
`make validate` прогоняет психометрию, атаку «20 сессий», подбор против базовых методов и ось ФСП с проверкой порогов (`checks: passed`), около 4 минут.
Доказательство: `Makefile` (цель `validate`), `backend/app/validation/`.

**Запуск одной командой.**
`docker compose up -d --build --wait` поднимает платформу без `.env` и сам заполняет демо-данные.
Доказательство: `docker-compose.yml`, `backend/tests/unit/test_compose_local_oneshot.py`, [INSTALL.md](INSTALL.md).

**Каждое требование ТЗ связано с автотестом.**
Таблица соответствия указывает для требования экран, код и файл теста.
Доказательство: [REQUIREMENTS.md](REQUIREMENTS.md).

## Психометрика

**Адаптивный тест на IRT 3PL.**
Уровень пересчитывается после каждого ответа (EAP), следующее задание выбирается там, где оно лучше всего различает уровни у порога грейда (информация Фишера).
Доказательство: `backend/app/services/cat.py`, [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md).

**Остановка, как только решение ясно.**
8–20 заданий: последовательная проверка гипотез (GLR) с зоной безразличия ±0,25 и апостериорная вероятность грейда.
Доказательство: `backend/app/services/cat.py` (`GLR_DELTA`, `GLR_ALPHA`), `cd backend && python tests/stop_reasons.py --n 400`.

**Параметрические семейства и контроль экспозиции.**
У каждого кандидата свои числа и фрагменты кода, доля показов задания ограничена методом Симпсона–Хеттера.
Доказательство: `backend/app/items/`, `backend/app/services/cat.py`.

**Карантин утёкших ключей.**
Ключ с аномальным ростом доли верных ответов автоматически уходит из выдачи: при утечке у 30 % кандидатов точность 88,9 %.
Доказательство: `backend/app/services/item_monitor.py`, `GET /api/v1/public/assessment/items`.

**Разделяющая сила с интервалами.**
Пара junior / middle различается с AUC 0,921 (95 % ДИ 0,904–0,936).
Доказательство: [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md#разделяющая-сила-auc-соседних-грейдов).

## Подбор и объяснимость

**Каждое место объяснено.**
Строки «плюс / минус / инфо» по каждому фактору с меткой источника и весом, «лучше N % кандидатов категории», сравнение до четырёх кандидатов; объяснение собирается из тех же вкладов, что и балл.
Доказательство: `backend/app/services/matching.py`, `backend/tests/unit/test_matching.py`, [SOLUTION.md](SOLUTION.md).

**Подтверждённое важнее заявленного.**
Навык весит по силе доказательства: тест 1,0, цитата в резюме 0,75, заявлено 0,55.
Доказательство: [README](../README.md#подбор), `backend/tests/unit/test_matching.py`.

**Ось «подтверждено ФСП» с доказанной монотонностью.**
Байесовская оценка с осторожной нижней границей (LCB): новый результат не понижает кандидата, ферма участий не даёт ничего.
Доказательство: `backend/tests/unit/test_fsp_engine_monotone.py`, `backend/tests/unit/test_fsp_lift_property.py`.

**Несколько категорий у кандидата.**
Вторую специализацию кандидат подтверждает отдельным тестом, работодатель находит его по этой роли.
Доказательство: `frontend/src/components/OtherCategories.tsx`, `backend/tests/unit/test_second_category.py`, [ORGANIZER_DECISIONS.md](ORGANIZER_DECISIONS.md).

**Рыночные квартили зарплат.**
При приглашении работодатель видит квартили ожиданий по категории, если в ячейке не меньше пяти человек.
Доказательство: `backend/app/services/market.py`, `backend/tests/unit/test_category_market.py`.

**Языковая модель помогает, но не решает.**
GigaChat или YandexGPT предлагают навыки только с дословной цитатой из резюме и не меняют балл, порядок и грейд; без ключей резюме разбирается правилами.
Доказательство: `backend/app/services/ai/providers.py`, `backend/app/services/skills.py`.

**Справедливость подбора.**
Пол, имя, регион и дата рождения не входят в балл; правило 4/5 и Skew@k считаются на том же подборе, что и выдача, в том числе при равной истинной релевантности: C# и Go при той же релевантности попадают в топ-10 чаще Python (1,62 и 1,73).
Доказательство: `backend/app/services/exposure_fairness.py`, `backend/tests/unit/test_fairness.py`, `python -m app.validation.fairness`, [VALIDATION_MATCHING.md](VALIDATION_MATCHING.md#неблагоприятное-воздействие-правило-45-и-skewk).

**Человек принимает решение.**
Платформа ранжирует и объясняет, но не отсеивает автоматически (ст. 16 152-ФЗ).
Доказательство: [SOLUTION.md](SOLUTION.md).

## Безопасность и защита от обмана

**Модель угроз на 13 атак.**
Для каждой атаки — защита в коде и место, где она измерена.
Доказательство: [THREAT_MODEL.md](THREAT_MODEL.md).

**Атака «20 чужих сессий» закрыта в продукте.**
На 400 людях и шести зёрнах сдача после атаки 7,2 % (6,1–8,2 %) при честной 6,5 % (5,5–7,5 %), в пределах интервала честной сдачи.
Доказательство: [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md), `backend/app/items/`.

**Сессия теста защищена сервером.**
Правильный ответ не уходит в браузер, ответ принимается по токену HMAC, время засекает сервер, повтор не засчитывается дважды (`Idempotency-Key`); случайное угадывание проходит тест в 0 % случаев.
Доказательство: `backend/tests/unit/test_idempotency.py`, [SOLUTION.md](SOLUTION.md).

**Сигналы недобросовестности.**
Уход со вкладки, копирование, слишком быстрые ответы и индекс l<sub>z</sub>* показываются пометкой; один сигнал — не нарушение, грейд не меняется.
Доказательство: `backend/app/services/session_marks.py`, [VALIDATION_INTEGRITY.md](VALIDATION_INTEGRITY.md).

**Защита от недобросовестных вакансий.**
Просьба денег, зарплата без оформления и отбор по внешности отмечаются в тексте вакансии; лимит приглашений и жалоба с паузой компании.
Доказательство: [TRUST_AND_ATS.md](TRUST_AND_ATS.md).

**Хранение по OWASP ASVS.**
Argon2id, контакты в AES-256-GCM с поиском по HMAC, политики PostgreSQL RLS под ролью без `BYPASSRLS`: 240 запросов с чужим идентификатором — 0 ответов 2xx.
Доказательство: `backend/app/core/security.py`, `backend/tests/unit/test_field_cipher.py`, `backend/tests/smoke_api.py`.

**Второй фактор, песочница и лимиты.**
Модерация под TOTP (RFC 6238), код кандидата выполняется в контейнере без сети, лимиты запросов с `Retry-After`.
Доказательство: `backend/app/services/totp.py`, `sandbox/`, [API_ERRORS.md](API_ERRORS.md).

## Интеграции

**API-ключи для ATS.**
Компания создаёт и отзывает ключ сама; хранится только SHA-256, ключ показывается один раз, выгрузка принимает `X-API-Key`.
Доказательство: `backend/app/api/v1/integrations.py`, `frontend/src/pages/employer/Integrations.tsx`, `backend/tests/unit/test_api_keys.py`.

**Вебхуки с защитой от повтора.**
Повторный `webhook-id` отклоняется, доставка только на проверенный адрес, контакты кандидата в вебхук не уходят.
Доказательство: `backend/app/services/webhooks.py`, `backend/tests/unit/test_webhook_replay.py`.

**OpenAPI 3.1 и `problem+json`.**
Снимок спецификации сверяется с приложением тестом, ошибки в формате RFC 9457 с машинными кодами.
Доказательство: [openapi.json](openapi.json), `backend/tests/unit/test_problems.py`.

**Живые числа стенда.**
Главная показывает счётчики из базы: кандидаты, семейства заданий, участники ФСП, компании.
Доказательство: `GET /api/v1/public/stats` (`backend/app/api/v1/public.py`).
