# ФСП Талант: что мы даём сверх ТЗ

ТЗ описывает работающий MVP обратного найма. Мы сделали платформу, которую можно ставить в эксплуатацию: тест с психометрией уровня международных экзаменов, подбор с объяснением каждого места, подписанные удостоверения, защита персональных данных по 152-ФЗ и OWASP. Каждая строка ниже ведёт к коду или документу, её можно проверить за минуту.

## Психометрика уровня мира

**Адаптивный тест на IRT 3PL.**
Каждый кандидат получает задания, которые точнее всего решают вопрос о его грейде, поэтому тест короче и точнее фиксированного.
ТЗ требует тест сопоставимой сложности → мы даём CAT с апостериорной оценкой EAP и выбором задания по информации Фишера у порога грейда.
Доказательство: `backend/app/services/cat.py`, [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md).

**Остановка по GLR.**
Тест заканчивается, как только решение статистически ясно: 8–20 заданий, ошибки 10 % с каждой стороны.
ТЗ требует вывод о грейде → мы даём последовательную проверку гипотез с зоной безразличия ±0,25.
Доказательство: `backend/app/services/cat.py` (`GLR_DELTA`, `GLR_ALPHA`), [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md).

**Контроль экспозиции Симпсона–Хеттера.**
Ни одно задание не становится «известным всем»: доля показов ограничена.
ТЗ требует устойчивость к распространению заданий → мы даём контроль экспозиции плюс параметрические семейства, где у каждого свои числа и фрагменты кода.
Доказательство: `backend/app/services/cat.py`, `backend/app/items/`.

**Карантин утёкших ключей.**
Если доля верных ответов по ключу растёт сверх ожидаемой, ключ автоматически уходит из выдачи; статистика открыта.
ТЗ требует защиту от утечки → мы даём мониторинг с карантином: при утечке у 30 % кандидатов точность 91,4 %.
Доказательство: `backend/app/services/item_monitor.py`, `GET /api/v1/public/assessment/items`, [README](../README.md#цифры-которые-можно-проверить).

**Разделяющая сила с интервалами.**
Тест уверенно отличает соседние грейды: AUC junior/middle 0,930 (95 % ДИ 0,912–0,946).
ТЗ требует категоризацию → мы даём её измеренное качество.
Доказательство: [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md#разделяющая-сила-auc-соседних-грейдов).

## Подбор и объяснимость

**Каждое место объяснено.**
Работодатель видит, почему кандидат на этом месте: строки «плюс / минус / инфо» по каждому фактору с меткой источника и весом.
ТЗ требует объяснимость → мы даём машинные коды причин, «лучше N % кандидатов категории» и сравнение до четырёх кандидатов.
Доказательство: [SOLUTION.md](SOLUTION.md), `backend/app/services/matching.py`.

**Подтверждённое важнее заявленного.**
Навык весит по силе доказательства: тест 1,0, цитата в резюме 0,75, заявлено 0,55.
ТЗ требует ранжирование по силе профиля → мы даём прозрачную шкалу доказательности.
Доказательство: [README](../README.md#подбор), `backend/tests/unit/test_matching.py`.

**Ось «подтверждено ФСП» с доказанной монотонностью.**
Новый результат соревнований никогда не понижает кандидата, ферма участий не даёт ничего.
ТЗ требует учесть ФСП → мы даём байесовскую оценку с нижней границей LCB и property-тесты.
Доказательство: [FSP_INTEGRATION.md](FSP_INTEGRATION.md), `backend/tests/unit/test_fsp_engine_monotone.py`, `test_fsp_lift_property.py`.

**Языковая модель помогает, но не решает.**
GigaChat или YandexGPT предлагает навыки только с дословной цитатой из резюме и не меняет балл, порядок и грейд.
ТЗ допускает ИИ-анализ → мы даём контролируемый ИИ в российских облаках с запасным разбором правилами.
Доказательство: `backend/app/services/ai/providers.py`, [SOLUTION.md](SOLUTION.md).

## Доверие и верифицируемые удостоверения

**W3C Verifiable Credentials 2.0.**
Достижение кандидата — подписанный документ, подлинность которого проверяет кто угодно без звонка в ФСП.
ТЗ требует показать достижения → мы даём криптографическую подпись Ed25519, `eddsa-jcs-2022`.
Доказательство: `backend/app/services/vc/issuer.py`, страница проверки на `/jury`.

**Open Badges 3 и SD-JWT.**
Значок совместим с мировыми кошельками, а кандидат раскрывает только нужные поля.
Доказательство: `backend/app/services/vc/issuer.py` (`OpenBadgeCredential`, `issue_sd_jwt`), `backend/tests/unit/test_vc.py`.

**Паспорт навыков по ссылке и QR-коду.**
Кандидат делится подтверждённым профилем одним касанием.
Доказательство: `frontend/src/pages/BadgePage.tsx`.

## Антифрод и честность

**Сессия теста защищена сервером.**
Правильный ответ не уходит в браузер, ответ принимается по HMAC-токену только на текущее задание, время засекает сервер, повтор несёт Idempotency-Key.
ТЗ требует честный тест → мы даём серверную защиту: случайное угадывание проходит тест в 0 % случаев.
Доказательство: [SOLUTION.md](SOLUTION.md), [README](../README.md#цифры-которые-можно-проверить).

**Сигналы недобросовестности для работодателя.**
Уход со вкладки, копирование, слишком быстрые ответы и индекс l<sub>z</sub>* показываются пометкой, грейд не трогают.
Доказательство: [SOLUTION.md](SOLUTION.md).

**Защита от недобросовестных вакансий.**
Просьба денег у кандидата, зарплата мимо оформления и отбор по внешности подписываются в тексте вакансии; лимит приглашений и жалоба с паузой компании.
Доказательство: [SOLUTION.md](SOLUTION.md), [TRUST_AND_ATS.md](TRUST_AND_ATS.md).

## Безопасность по OWASP ASVS

**Пароли Argon2id.**
Параметры OWASP, старые bcrypt-хеши прозрачно переписываются при входе.
Доказательство: `backend/app/core/security.py`, [SOLUTION.md, гл. 10](SOLUTION.md#10-безопасность-и-152-фз).

**Шифрование контактов AES-256-GCM и поиск по HMAC.**
Почта и телефон в базе зашифрованы по NIST SP 800-38D; вход ищет по HMAC (blind index), а не по шифртексту.
Доказательство: `backend/app/models/participant.py`, `backend/app/models/employer.py`.

**Политики PostgreSQL RLS.**
Приложение работает ролью без прав суперпользователя и без `BYPASSRLS`; 240 запросов с чужим идентификатором — 0 ответов 2xx.
Доказательство: `backend/tests/smoke_api.py`, [README](../README.md#персональные-данные-и-безопасность).

**Второй фактор и изолированная песочница.**
Модерация закрыта TOTP (RFC 6238), код кандидата выполняется в контейнере без сети с корнем только для чтения.
Доказательство: `backend/app/services/totp.py`, `sandbox/`.

**Лимиты запросов с `Retry-After`.**
Вход, регистрация, письма, приглашения и поиск ограничены; при сбое хранилища лимитов вход закрывается.
Доказательство: `backend/app/api/errors.py`, [API_ERRORS.md](API_ERRORS.md).

## Приватность по 152-ФЗ

**Раздельные согласия с отпечатком текста.**
Согласие на обработку (ст. 9) и на распространение (ст. 10.1) хранятся с версией и SHA-256 принятого текста.
Доказательство: [README](../README.md#персональные-данные-и-безопасность), `backend/app/api/v1/legal.py`.

**Анонимная выдача и k-анонимность витрины.**
Карточка в выдаче без имени и контактов; ячейка банка меньше пяти человек скрыта, чтобы число не указывало на конкретного человека.
Доказательство: `backend/app/services/search/pipeline.py` (`BANK_MIN = 5`).

**Защита несовершеннолетних.**
Кандидат 15–17 лет попадает в поиск только после согласия законного представителя по подписанной ссылке (ч. 6 ст. 9).
Доказательство: `backend/app/services/guardian.py`, [USER_GUIDE.md](USER_GUIDE.md#законный-представитель).

**Отзыв, стирание и закрытие для одной компании.**
Отзыв согласия закрывает контакты сразу, удаление аккаунта стирает данные немедленно; каждый просмотр контактов в журнале.
Доказательство: `backend/app/services/account_export.py`, [README](../README.md#персональные-данные-и-безопасность).

## Справедливость подбора

**Правило четырёх пятых.**
Доля показов групп сравнивается с порогом 0,8; группы меньше пяти человек не сравниваются.
ТЗ требует корректный подбор → мы даём встроенный контроль справедливости экспозиции.
Доказательство: `backend/app/services/exposure_fairness.py`, `backend/tests/unit/test_fairness.py`.

**Человек принимает решение.**
Платформа ранжирует и объясняет, но не отсеивает автоматически (ст. 16 152-ФЗ).
Доказательство: [SOLUTION.md](SOLUTION.md).

## Доступность WCAG 2.2 AA

**Ноль серьёзных и критичных нарушений.**
axe-core проверяет 15 экранов в светлой и тёмной темах на 1440 и 390 px по правилам WCAG 2.0, 2.1 и 2.2 AA, правила не отключаются.
ТЗ требует удобный интерфейс → мы даём измеренную доступность: контраст пар посчитан, цели от 24 px, видимый фокус, `prefers-reduced-motion`.
Доказательство: [DESIGN.md](DESIGN.md#проверка-интерфейса), `frontend/e2e/`.

**Lighthouse: доступность 100, производительность 84–100.**
Замер на стенде, мобильный и десктопный профили (в README — PR #309).

## Валидация и воспроизводимость

**Симуляция со скрытой правдой.**
2000 кандидатов, фиксированное зерно, каждая цифра воспроизводится одной командой.
Доказательство: `python -m app.validation.assessment --n 2000 --seed 7`, `python -m app.validation.matching`.

**Бутстрап-интервалы и предрегистрация.**
Метрики даются с 95 % ДИ, эксперимент по ранжированию зафиксирован до запуска на отложенных зёрнах.
Доказательство: [PREREG_MATCHING_2026-10.md](PREREG_MATCHING_2026-10.md), [VALIDATION_MATCHING.md](VALIDATION_MATCHING.md).

Жюри загружает свои пары и получает метрики подбора: `python -m app.validation.matching --import pairs.json`, а без установки — страница `/evaluate`.

**Графики валидации.**
