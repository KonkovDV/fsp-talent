## Ответы постановщика на Q&A и как они учтены

| Ответ постановщика | Как сделано | Где в коде |
|---|---|---|
| Грейд определяется только тестом категории | Грейд даёт только основной тест специализации. Тест по вакансии, задачи недели, задания работодателя и результаты ФСП грейд не меняют | `app/services/assessment.py`, `is_vacancy_session` |
| Неподтверждённый грейд показывается ниже | До теста грейд помечен как заявленный и в оценке соответствия весит 0,85 от подтверждённого; в карточке строка «указан кандидатом, тестом не подтверждён» | `app/services/matching.py` |
| Повышение грейда — отдельным тестом | Тест на уровень подтверждает только этот уровень. Уверенный результат выше (от 90 % за следующий порог) даёт рекомендацию пройти тест на ступень выше, но грейд сам не растёт | `app/services/cat.py` (`RECOMMEND_NEXT_P`), `assessment.py` |
| Ограничение по времени, но тест ниже без потери попытки | Не сдали — тест на уровень ниже доступен сразу. Пересдача того же уровня — через 7 дней, прерванная попытка засчитывается. После смены грейда следующее повышение — через 90 дней | `retake_available_at`, `GRADE_COOLDOWN_DAYS`, `RETAKE_INTERVAL_DAYS` |
| Тест устойчив к утечке банка | Параметрические семейства вместо банка, вводимый ответ, карантин утёкших ключей, вопросы на понимание не повторяются во второй попытке больше чем на 40 % | `app/items/`, `item_monitor.py`, [VALIDATION_ASSESSMENT.md](VALIDATION_ASSESSMENT.md) |
| Языковая модель допустима, открытые предпочтительнее, видеокарта не нужна | Письменный ответ разрешает облачные модели, в том числе зарубежные. Мы берём GigaChat и только обезличенный текст: навык принимается, если цитата из резюме дословная. Без ключа работает разбор правилами. Тест и подбор модель не используют | `app/services/ai/assistant.py` |
| Вакансии не импортируем | Вакансии создают только работодатели на платформе, демо-вакансии вымышлены | `app/api/v1/vacancies.py`, `seed/` |
| Регулярные задания пишет работодатель, проверяет система или работодатель | Задание с эталоном (число, выбор) проверяет система, открытое (скрипт, бизнес-решение) — работодатель. Задание для всех кандидатов специализации или одному кандидату | `app/services/tasks.py`, `app/api/v1/tasks.py` |
| ФСП ID — единая точка входа, вход можно имитировать | «Войти через ФСП ID» на входе и регистрации: OIDC с PKCE, демо-провайдер вместо Keycloak. Новый человек проходит экран согласий, аккаунт создаётся из реестра. Регистрация по email осталась | `app/api/v1/auth.py`, [FSP_INTEGRATION.md](FSP_INTEGRATION.md#вход-в-платформу-через-фсп-id) |
| Кандидат может закрыть контакты | Глобальный отзыв согласия и закрытие контактов для одной компании: компания получает 403 `contacts_revoked`, событие пишется в журналы | `candidates.py` (`/revoke-contacts`), [TRUST_AND_ATS.md](TRUST_AND_ATS.md) |
| Нужна связь после принятия приглашения | Переписка по каждому принятому приглашению, после закрытия контактов — только чтение | `app/api/v1/messages.py` |
| Достижения ФСП: соревнования не ранжировать по статусу, учитывать результат и количество | Методика `v3.2.0`: класс результата по месту (победитель, призёр, топ-10 %, верхняя половина, участие с весом 0), статус не учитывается. В сумму входят пять сильнейших событий. Количество результатов работает через байесовское сжатие: участие весит 0, среднее не поднимает и может опустить нижнюю границу. Разряд — факт реестра и в балл не входит | `app/services/scoring/engine.py`, [README](../README.md#две-оси-профиля) |
| Демо-аккаунты жюри | Пока включён демо-режим, смена пароля и удаление адресов `*.demo` и `@demo.talent` закрыты. Стенд возвращается каждую ночь в 04:10 | `app/core/demo_guard.py`, `seed/reset_demo.py` |
| Продление теста у границы не включено | Тест заканчивается на 20-м задании. Одно продолжение до 6 заданий на 2000 кандидатах, зерно 7, дало 76,9 % сдавших среди тех, кто на уровне, при пороге 77 % и ложные сдачи 9,8 % при пороге 8,5 % | `MAX_ITEMS` в `app/services/cat.py` |
| Несовершеннолетние участники | Скрыты из поиска и рейтинга без согласия законного представителя | `app/services/profile.py` (`adult_cutoff`) |
| Зарплата — до вычета НДФЛ | Поля вилки названы «Зарплата до вычета НДФЛ, ₽ в месяц», в API — `salary_from_gross`, `salary_to_gross` | `InviteDialog.tsx`, `app/models/offer.py` |
| Ресурсы стенда | Обычная машина: 8 контейнеров, около 1,5 ГБ памяти, без GPU | [INSTALL.md](INSTALL.md) |
| «Отрасль» в ТЗ — направление ИТ | Шаг опроса называется «Направление и специализация», поле предметной области необязательно | `frontend/src/components/SurveyCard.tsx`, `app/services/survey.py` |

| FTT.6 | Свои данные: синтетика или открытые источники. Парсинг чужих вакансий — не продуктовая механика | Сид и симуляция свои. Импорта вакансий нет |
| WA.1 | Достаточно основных направлений, если путь от теста до приглашения целый | Одиннадцать специализаций и пять грейдов. Ширина справочника оценку не поднимает, путь целый |
| WA.2 | Справочник может включать дизайнеров. Приоритет — роли, которые проверяются тестом | В справочнике технические роли. Отдельного теста для дизайнеров нет |

На встрече 6 октября сказали то, чего нет в таблице. Машина проверки — около 32–64 ГБ памяти и порядка 8 ядер, без видеокарты; наш стенд меньше, около 1,5 ГБ. После срока сдачи смотрят дату коммитов: идею решения не меняют, упавший контейнер можно поднять снова. Keycloak в обычный запуск не входит, хватает имитации входа. Переписка на платформе на оценку не влияет, мы её оставили. Объёма выборки и живых кандидатов для проверки не требовали: жюри смотрит руками и само проходит пробный тест. Домен почты на решение не влияет.
