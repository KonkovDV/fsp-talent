## 1. Задания от работодателя (ТЗ 2.1, «регулярные задания»)

Ответ заказчика: регулярное задание пишет работодатель. Если есть эталон ответа, проверяет система; открытые
задания (скрипт, бизнес-решение) оценивает работодатель. Задание можно выложить для всех или дать одному кандидату.

- Модель: `employer_tasks`, `task_submissions`; поля карточки `participants.employer_task_title/passed/at`.
  Миграция `0022_employer_tasks` (down_revision `0021_drop_legacy_bank`, обратимая).
- Типы ответа: `number` (эталон — целое число), `choice` (2–8 вариантов, один верный), `open` (свободный текст до
  4000 знаков, «решение или подход к решению»).
- Аудитория: `public` — все кандидаты выбранной специализации; `addressed` — один кандидат из поиска или подборки
  (анонимный id карточки). Необязательные: вакансия компании, срок сдачи. Закрыть приём ответов можно вручную.
- Число и выбор проверяются сразу; эталон кандидату не отдаётся, пока он сам не ответил. Открытый ответ получает
  статус «на проверке»; работодатель ставит «зачтено / не зачтено» и короткий комментарий.
- Вердикт попадает в анонимную карточку строкой «Задание работодателя «…»: зачтено, вчера»
  (`app/services/tasks.py: card_signal`, вызов в `search/pipeline.py`); в подборке по потребности строка видна
  в «Почему в выдаче» и под навыками.
- Доступ: работодатель видит и проверяет только свои задания (чужое — 404); кандидат видит общие задания своей
  специализации и адресованные ему (чужое адресное — 404). Один ответ на задание (409 `task_answered`), закрытое или
  просроченное — 409 `task_closed`. Лимит 30 заданий в сутки на компанию (`too_many`).
- Уведомления (колокольчик + письмо без персональных данных другой стороны): кандидату — адресное задание
  (`task_new`) и проверка открытого ответа (`task_reviewed`); работодателю — новый ответ (`task_submission`,
  кандидат назван категорией).
- «Задача недели» осталась и подписана как сгенерированная платформой по тексту вакансии.

API:

| Метод | Путь | Кто |
|---|---|---|
| POST | `/api/v1/tasks/` | работодатель: создать |
| GET | `/api/v1/tasks/mine` | работодатель: свои задания со счётчиками ответов |
| GET | `/api/v1/tasks/{id}/submissions` | работодатель: ответы (кандидат — категория) |
| POST | `/api/v1/tasks/{id}/close` | работодатель: закрыть приём |
| POST | `/api/v1/tasks/submissions/{id}/review` | работодатель: `{passed, comment}` для открытого ответа |
| GET | `/api/v1/tasks/for-me` | кандидат: общие своей специализации + адресные |
| POST | `/api/v1/tasks/{id}/answer` | кандидат: `{answer_text}` или `{answer_index}` |

Экраны: `/employer/tasks` (список, «Новое задание», ответы и проверка), кнопка «Дать задание» в карточке кандидата
(поиск и подборка), `/candidate/tasks` (решение), блок «Задания от работодателей» на обзоре кандидата.

Демо (`seed/demo_activity.py`, идемпотентно): у hr@sibcode.demo три задания — общее «Сколько строк вернёт JOIN»
(эталон 500, три ответа), общее открытое «Платёж списался дважды» (один ответ зачтён, один ждёт проверки),
адресное fsp001@demo.talent «Индекс для выборки заказов» (выбор варианта).
Как показать: войти hr@sibcode.demo → «Задания» → «Платёж списался дважды» → проверить ответ; войти
fsp001@demo.talent → «Задания» → решить; в поиске работодателя в карточке появится строка с вердиктом.

## 2. Вход через ФСП ID

Ответ заказчика: ФСП ID — единая точка входа; вход имитируем, регистрация по email остаётся.

- Кнопка «Войти через ФСП ID» на входе кандидата и «Продолжить через ФСП ID» на регистрации.
- Тот же OIDC code flow + PKCE, что и привязка, но state не привязан к аккаунту, а адрес возврата свой:
  `/auth/fsp-callback` (привязка — `/candidate/fsp-callback`). Демо-провайдер принимает оба адреса; код,
  выданный для одного адреса, другой поток не примет. State и код одноразовые.
- `POST /api/v1/auth/fsp/authorize` → адрес страницы провайдера.
- `POST /api/v1/auth/fsp/callback {code, state}` → `signed_in` с токенами, если ФСП ID уже привязан к аккаунту;
  иначе `needs_consent` с одноразовым билетом (Redis, 15 минут) и данными реестра для показа.
- `POST /api/v1/auth/fsp/signup {ticket, consents}` → без обязательных согласий (terms, pd_candidate) — 422
  `consent_required`, билет не тратится; с согласиями аккаунт создаётся из реестра (`ingest_from_fsp`), согласия
  записываются, выдаются токены. Повтор билета — 400 `fsp_ticket_invalid`.
- Такой аккаунт работает без email и пароля (ФСП ID — поставщик личности); для связи кандидат добавляет Telegram
  или телефон в профиле. Писем такому кандидату нет, уведомления — в колокольчике.
- Как показать: «Вход» → «Войти через ФСП ID» → FSP001 / test (привязанный fsp001) или FSP2000–FSP2099 / test
  (новый человек, экран согласий).

## 3. Закрыть контакты для одной компании

- Кандидат в «Приглашениях» у принятого приглашения: «Закрыть контакты для этой компании» (с подтверждением).
- `POST /api/v1/candidates/me/offers/{id}/revoke-contacts`: закрывает все принятые приглашения этой компании;
  `GET /offers/{id}/contacts` отвечает 403 `contacts_revoked`; контакты по откликам на вакансии этой компании тоже
  закрыты, пока компания не получит новое принятое приглашение. Пишутся `consent_logs` (`contacts_revoked`) и
  `access_logs` (`contacts_revoked`, попытки после — `contacts_denied_revoked`); компании уходит уведомление
  `offer_contacts_revoked`. Глобальный отзыв согласия pd_candidate остался как был.
- Код ошибки добавлен в `app/api/errors.py` и `docs/API_ERRORS.md`.

## 4. Переписка после принятия приглашения

- `GET/POST /api/v1/offers/{id}/messages` (обе стороны, только свои приглашения; чужое — 404). Открывается после
  принятия; после закрытия контактов — только чтение. Счётчик непрочитанных `unread_messages` в списках приглашений
  обеих сторон, уведомление `message_new` без текста сообщения. Лимит 60 сообщений в час.
- Экран: кнопка «Переписка» в «Приглашениях» кандидата и работодателя.
- При удалении аккаунта ответы на задания и сообщения кандидата стираются, вердикты остаются анонимными.

## 5. Формулировки

- «Отрасль» в ТЗ — это направление ИТ, то есть специализация. Шаг опроса называется «Направление и специализация»,
  поле `industry` подписано «Предметная область (необязательно)» и стало необязательным (по умолчанию `any`).
