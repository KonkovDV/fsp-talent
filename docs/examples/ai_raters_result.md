# Слепая разметка двумя ИИ-оценщиками: результат расчёта

Оба оценщика — не люди, а автоматические оценщики на основе языковых моделей (LLM-as-judge). Оценщик A заполнил `ai_rater_a.csv`, оценщик B — `ai_rater_b.csv`. Каждый работал отдельно, по одной рубрике, видел только лист `blind_pairs_2029.csv`. Ключ `blind_pairs_2029.key.json` и баллы модели им не показывали. Пояснения и оговорки — в [VALIDATION_MATCHING.md](../VALIDATION_MATCHING.md#слепая-разметка-два-ии-оценщика-11102026).

Расчёт выполнен кодом `backend/app/validation/matching.py` 11.10.2026, Linux x86-64, Python 3.12.15.

SHA-256 входных файлов:


## Согласие оценщиков

```
$ python -m app.validation.matching --kappa ../docs/examples/ai_rater_a.csv ../docs/examples/ai_rater_b.csv
взвешенная каппа 0.97 на парах из двух файлов
порог годности 0,6: да
```

Оговорка: оба оценщика — языковые модели, вероятно на одной базовой модели, поэтому высокая κ показывает согласованность рубрики, а не согласие экспертов-людей; общие искажения базовой модели она не выявит.

Те же функции модуля без округления (`quadratic_weighted_kappa`, `cohen_kappa` на `read_rater_labels`): квадратично взвешенная κ 0,9739, κ Коэна 0,9368, точное совпадение 191 из 200 (95,5 %). Все 9 расхождений — на одну ступень: p044 (2/3), p059 (2/1), p064 (2/1), p095 (2/3), p121 (1/2), p122 (1/2), p123 (2/1), p125 (1/2), p178 (2/1).

## Слияние и метрики подбора

Слияние ждёт ключ рядом с первым файлом, под именем `ai_rater_a.key.json`. Ключ — копия `blind_pairs_2029.key.json`, в репозиторий второй раз не кладётся:

```
$ cp ../docs/examples/blind_pairs_2029.key.json /tmp/ai_rater_a.key.json
$ cp ../docs/examples/ai_rater_a.csv ../docs/examples/ai_rater_b.csv /tmp/
$ python -m app.validation.matching --merge-raters /tmp/ai_rater_a.csv /tmp/ai_rater_b.csv --merged /tmp/merged.jsonl
слито 200 пар в /tmp/merged.jsonl
```

Результат слияния (среднее двух оценок с округлением вниз) лежит здесь же: `ai_raters_merged.jsonl`. Распределение согласованных меток 0/1/2/3: 37/72/67/24.
