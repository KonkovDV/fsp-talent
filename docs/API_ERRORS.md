# Коды ошибок API

Любая ошибка возвращается как RFC 9457 (`Content-Type: application/problem+json`) и сохраняет прежние поля:

```json
{"type": "/problems/E01", "title": "Вход", "status": 403, "instance": "/api/v1/auth/participant/token",
 "problem": "E01",
 "error": {"code": "email_not_verified", "message": "Email не подтверждён: введите код из письма", "details": {"email": "a@b.ru", "role": "participant"}},
 "detail": "Email не подтверждён: введите код из письма"}
```

`problem` — класс E01–E20. Конкретный код по-прежнему в `error.code`. Каталог классов: `GET /api/v1/problems`. Поле `detail` повторяет текст для старых клиентов. Для ошибки проверки полей (422) `detail` и `error.details` содержат список полей. У ответа 429 есть заголовок `Retry-After`.

Повторная регистрация уже подтверждённого адреса отвечает 202 `verification_sent`, как новая, и не показывает код. Письмо на этот адрес говорит, что аккаунт уже есть. Код `email_taken` остаётся на гонку двух запросов, которые создают одну строку.

| Класс | Название |
|---|---|
| `E01` | Вход |
| `E02` | Доступ |
| `E03` | Не найдено |
| `E04` | Конфликт |
| `E05` | Поля запроса |
| `E06` | Слишком часто |
| `E07` | Подтверждение почты |
| `E08` | Согласие |
| `E09` | Тест |
| `E10` | Приглашение |
| `E11` | Задание |
| `E12` | Метод |
| `E13` | Уже нет |
| `E14` | Слишком большой запрос |
| `E15` | Сбой сервера |
| `E16` | Сервис недоступен |
| `E17` | Грейд |
| `E18` | Сессия теста |
| `E19` | Вилка |
| `E20` | Демо-аккаунт |
