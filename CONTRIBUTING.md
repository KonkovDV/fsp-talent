# Участие в разработке

Спасибо, что хотите улучшить ФСП Талант. Здесь — как поднять окружение, какие проверки пройти до пул-реквеста и какие правила продукта нельзя менять незаметно.

Об ошибке или идее сообщайте через [Issues](https://github.com/KonkovDV/fsp-talent/issues/new/choose). Об уязвимости — только частным сообщением, см. [SECURITY.md](SECURITY.md). Участвуя, вы соглашаетесь с [кодексом поведения](CODE_OF_CONDUCT.md).

## Окружение

- **Всё в Docker.** `docker compose up -d --build --wait` (или `make demo`) поднимает базу, API, фоновые задачи, интерфейс и демо-данные. Подробно — [docs/INSTALL.md](docs/INSTALL.md).
- **Без Docker.** Python 3.12, Node.js 20+, PostgreSQL 16 с pgvector и Redis 7 — [INSTALL.md, раздел 10](docs/INSTALL.md#10-запуск-без-docker-для-разработки). Проверка окружения: `make doctor LOCAL=1`.

Карта кода — в [README](README.md#разработка), главные решения — в [ARCHITECTURE.md](ARCHITECTURE.md) и [docs/adr/](docs/adr/README.md).

## Ветки и коммиты

- Работайте в отдельной ветке и открывайте пул-реквест в `main`. Небольшой пул-реквест с одной целью проверяется быстрее.
- Сообщения коммитов — по [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/): `feat`, `fix`, `docs`, `test`, `refactor`, `chore`, `ci`. Описание — по-русски, в повелительном наклонении: `fix: вернуть контакты после повторного согласия`.
- Не переписывайте опубликованную историю `main` и не отключайте проверки хуков.

## Проверки до пул-реквеста

Те же шаги выполняет CI (`.github/workflows/ci.yml`), но локально они быстрее.

| Что | Команда |
|---|---|
| Стиль Python | `pip install "ruff==0.16.10"` и `ruff check backend/app backend/seed backend/tests` |
| Юнит-тесты backend | `cd backend && python -m pytest tests/unit -q` |
| Интерфейс | `cd frontend && npm run type-check && npm test && npm run build` |
| Требования без базы | `make accept` |
| Тест и подбор на синтетике | `make validate` — если менялись тест, подбор или ось ФСП |
| Сквозной путь | `make demo`, затем `make check` и `npx playwright test` в `frontend/` |

Часть юнит-тестов перезапускает эталоны заданий на Node.js, Go, Java, Kotlin и .NET. Без этих компиляторов такие тесты локально пропускаются, в CI они обязательны.

## Документация и опубликованные цифры

- Каждое число в документации печатается командой с фиксированным зерном. Если изменение двигает цифры теста, подбора или оси ФСП, перезапустите команду из таблицы [«Цифры, которые можно проверить»](README.md#цифры-которые-можно-проверить) и обновите README, `docs/INSTALL.md`, `docs/VALIDATION_*.md` и `docs/tools/build_pitch.mjs`.
- `python tests/doc_numbers.py` в `backend/` сверяет число юнит-тестов, покрытие и хеш набора подбора с документацией. Шаг идёт в CI после юнит-тестов и падает при расхождении.
- Значения со страницы методики (`frontend/src/methodFigures.ts`) должны стоять в той же таблице README.
- Ссылки и якоря во всех `.md`, число ячеек в таблицах и закрытие блоков кода проверяют юнит-тесты `test_markdown_*.py`.
- Новый код ошибки API добавляется в `ERROR_CODES`, в карту классов `backend/app/api/problems.py` и в [docs/API_ERRORS.md](docs/API_ERRORS.md).
- После изменения маршрутов или схем обновите снимки спецификации: `python -m app.tools.dump_openapi --write` в `backend/` переписывает `docs/openapi.json` и `docs/openapi_paths.txt`, тест `test_openapi_paths.py` сверяет их с приложением.

## База данных

Схема живёт в одной ревизии Alembic, `0001_initial`. Новая таблица, колонка или индекс добавляются в неё же. На уже работающей базе `app.core.schema_sync` при старте досоздаёт недостающее и ничего не удаляет и не меняет. Изменение, которое удаляет или переписывает данные, обсуждается отдельно и сопровождается планом отката.

## Персональные данные и юридические тексты

- Не коммитьте секреты и настоящие персональные данные: CI ищет секреты (gitleaks), демо-данные только вымышленные.
- Тексты согласий и правил лежат в `backend/app/legal/docs/` с версией во вступительном блоке. В базе хранится версия и SHA-256 принятого текста, поэтому любая правка текста требует новой версии.

## Правила продукта

Эти правила закреплены тестами. Изменение, которое их нарушает, обсуждается в Issue до кода:

- Грейд ставит только основной тест специализации. Результаты ФСП, задания работодателя и тест по вакансии грейд не меняют.
- Ось ФСП только поднимает кандидата внутри категории. Отсутствие истории ФСП не штрафует, участие без результата весит 0.
- Зарплатная вилка и вероятность согласия видны на карточке и место в подборке не двигают.
- Пометки честности теста, отметки гостевого просмотра и ответ «Да, если…» не меняют балл и порядок.
- Языковая модель предлагает навыки только с дословной цитатой и не меняет балл, порядок и грейд.
- Контакты открываются только после согласия кандидата и только при действующем согласии на обработку.
- Регистрация открыта с 15 лет; кандидат 15–17 лет попадает в поиск только после согласия законного представителя.
