# ФСП Талант

Обратный найм для трека ФСП на LCT-2026. Работодатель ищет категорию участников по протоколам и отправляет оффер с зарплатой. Имя и контакты открываются только после согласия кандидата.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec -u appuser backend python -m seed.generate_seed
```

Миграция выполняется при старте backend. Сайт: http://localhost (nginx). API (8010), фронтенд (3010), PostgreSQL (5432) и Redis (6379) опубликованы только на 127.0.0.1; снаружи доступен только nginx.

Письма с кодами подтверждения видны в Mailpit: http://localhost:8025 (на стенде — настоящий SMTP через `MAIL_MODE=smtp` и `SMTP_*` в `.env`).

Демо-вход (пароль у всех `demo12345`, компании вымышленные):

| Кто | Email | Что показывает |
|-----|-------|----------------|
| Кандидат | fsp001@demo.talent | привязан ФСП ID, подтверждённые результаты |
| Кандидат | fsp002@demo.talent | ФСП, специализация ИБ |
| Кандидат | nofsp@demo.talent | нет истории ФСП: категория по опросу и тесту |
| Работодатель | hr@sibcode.demo | поиск, приглашения, вакансии |

## Аккаунты и согласия

- Регистрация обеих ролей по email с подтверждением кодом из 6 цифр или ссылкой (ТЗ 2.2 п. 4). Код хранится только как HMAC, живёт 30 минут, 5 попыток, повторная отправка не чаще раза в минуту. Есть сброс пароля.
- История ФСП для регистрации не нужна (ТЗ 2.1). ФСП ID привязывается в профиле; в моке — FSP2000–FSP2099 с паролем `test`, в продакшене — вход через ФСП ID в Keycloak. Данные ФСП главнее для даты рождения и региона.
- Согласие на обработку ПДн — отдельный документ (ч. 1 ст. 9 152-ФЗ в ред. 156-ФЗ), публичная страница требует ещё одного согласия на распространение (ст. 10.1). Тексты лежат в `backend/app/legal/docs/`, в БД хранится версия и SHA-256 принятого текста; отзыв — в профиле.
- Вместо даты рождения спрашиваем «мне есть 18» (минимизация данных); несовершеннолетний скрыт из поиска до согласия представителя.
- Все ошибки API в одном формате с машинным кодом: [docs/API_ERRORS.md](docs/API_ERRORS.md).

## Две оси профиля

Грейд не выводится из соревнований. Его подтверждает тест (см. ниже); пока теста нет, грейд берётся из самооценки или стажа и помечается как неподтверждённый. Ось «подтверждено ФСП» считается отдельно, версия `v2.0.0`:

```
p = 1 - (place - 0.5) / N                 процентиль Хазена
q = W(разряд ЕВСК) * p                    качество результата
w = 2^(-месяцы / 18) / sqrt(размер команды)
μ = (Σ w q + K μ0) / (Σ w + K)            K=2, μ0=0.30
σ = sqrt(0.04 / (Σ w + K))
ранжирование по LCB = μ - σ
```

Это апостериор нормально-нормальной модели с известной дисперсией наблюдения τ²=0.04 и приором N(0.30, τ²/K); веса w — дробные псевдонаблюдения. σ не зависит от разброса результатов, LCB = μ − 1σ (≈ 84 % односторонней уверенности). Командный результат уменьшает вес доказательства и расширяет σ, а не снижает уровень. Разряд-эквивалент — упрощённая лестница ЕВСК; МС и КМС требуют не меньше 6 участников.

## Опрос и тест на грейд

Категория = опрос (специализация, отрасль, цель: работа или стажировка) + заявленный грейд + тест (ТЗ 2.1). Специализация задаёт роль в категории и состав теста; грейд подтверждается отдельно для каждой специализации. Шестая дисциплина ФСП «программирование систем ИИ» (ЕКП 2026) учтена и связана со специализацией ML.

Тест адаптивный и устойчив к утечке:

- Задания по одному из **параметрических семейств** с пятью уровнями сложности (Python, SQL, JavaScript, алгоритмы, графы, сети, безопасность, ML, встраиваемые системы). Ответ вычисляется кодом; тест `test_item_families.py` перезапускает каждый фрагмент в Python, Node.js и SQLite. Статичных концептуальных вопросов не больше 30 %. LLM в рантайме не используется.
- **IRT 3PL** (угадывание 1/4), апостериор на сетке, **CAT на классификацию**: задание выбирается по информации в точке порога грейда, randomesque, доли тем по плану специализации, 8–20 заданий, остановка при уверенности 90 %.
- Грейд подтверждён при P(уровень) ≥ 75 %, повышение на ступень — при P(следующий уровень) ≥ 90 %. Тест не понижает подтверждённый грейд; после повышения 90 дней ожидания; пересдача того же уровня — через 7 дней, прерванная попытка засчитывается.
- Правильный ответ не уходит на клиент до конца; ответ принимается по HMAC-токену текущего задания; время засекает сервер.
- **Мониторинг утечки**: дрейф решаемости по каждому ключу с оценкой способности без заданий того же семейства; при z ≥ 3,5 ключ уходит в карантин. Статистика открыта: `GET /api/v1/public/assessment/items`. Калибровка трудности: `python -m app.validation.calibrate`.
- Навыки с ≥ 75 % верных на ≥ 3 заданиях получают отметку «подтверждён тестом».

Проверка симуляцией с атакой утечкой: [docs/VALIDATION_ASSESSMENT.md](docs/VALIDATION_ASSESSMENT.md) (`python -m app.validation.assessment`).

## Подбор: потребности и объяснимый скор

Работодатель описывает **потребность** (специализация, грейд, обязательные и желательные навыки, отрасль, стажировка); каждое изменение — новая версия, шорт-лист помнит версию, по которой выбран кандидат, и показывает воронку. Для потребности считаются **рекомендуемые категории** «специализация × грейд».

Порядок выдачи — один **разложимый скор** (`app/services/matching.py`): навыки 0,40, грейд 0,25, специализация 0,15, тест 0,08, ФСП 0,05, текст 0,04, отрасль 0,03. Неприменимые факторы выбрасываются с перенормировкой весов, поэтому кандидат без истории ФСП не штрафуется. Навык весит по силе доказательства (тест 1,0, цитата из резюме 0,95, заявление 0,8), близкая технология даёт частичный зачёт. В карточке — полосы факторов и строки «плюс / минус / инфо». Фильтры «с ФСП / без ФСП» и «стажировка».

Качество проверено на синтетическом наборе со скрытой правдой против случайного порядка и базовой линии по ключевым словам, с абляциями: [docs/VALIDATION_MATCHING.md](docs/VALIDATION_MATCHING.md) (`python -m app.validation.matching`, есть `--export` и `--import` для разметки жюри).

## Поиск

Жёсткие фильтры в SQL: профиль открыт, несовершеннолетний только с согласием законного представителя (сам участник этот флаг не меняет), роль, грейд, дисциплина, минимальный разряд. Дальше лексический ранг (`ts_rank` + триграммы) и опционально векторный поиск. Слияние — RRF с K=60. Итоговый порядок: покрытие навыков, грейд подтверждён тестом, RRF, лучший LCB (при выбранной дисциплине — LCB именно в ней). В RRF отдельным рангом входит лучший θ теста. Фильтр `assessed_only` оставляет только подтверждённые грейды. `total` в ответе — размер ранжируемого пула (≤ 1000), флаг `pool_capped` говорит, что пул обрезан. Карточка без имени (псевдонимная): статус соревнования, год и корзина процентиля, без названия события и точного места.

Плотные эмбеддинги выключены (`EMBEDDINGS_MODE=off`), пока не подключён `sentence-transformers`. Разбор резюме работает правилами; GigaChat добавляет навыки только если цитата дословно есть в тексте и задан `GIGACHAT_CREDENTIALS`.

## Удостоверения

W3C VC Data Model 2.0, Data Integrity `eddsa-jcs-2022`. Издатель — платформа, не ФСП: она подтверждает, что результат получен из системы ФСП. Проверка: `GET /api/v1/public/issuer` и `POST /api/v1/public/credentials/verify`.

## Правовые границы прототипа

Контакты видны только после принятия оффера; событие пишется в `consent_logs`, просмотр — в `access_logs`. В `consent_logs` также пишутся отказ от оффера и каждое переключение `is_visible` / `public_profile`. Ответ на оффер и отзыв сериализованы блокировкой строки, активный оффер на пару «работодатель–кандидат» ровно один (уникальный индекс). Именная страница и лидерборд недоступны несовершеннолетним. ИИ только предлагает навыки и разбирает запрос, решение остаётся за человеком.

## Ограничения прототипа

- Все данные синтетические: `RealFSPAdapter` ждёт спецификацию API ФСП.
- Нет потока согласия законного представителя; в демо несовершеннолетние в поиск не попадают.
- Канонизация VC не проверена на тест-векторах W3C; нет статуса отзыва и ротации ключа.
- Трудность заданий откалибрована только на симуляции; на реальных ответах нужна калибровка (`app.validation.calibrate`).
- Rate limit есть на вход, поиск, старт теста и приглашения (50 в сутки), но при недоступном Redis пропускает запросы. Refresh-эндпоинт без отзыва, фронтенд его не использует; токены хранятся в `localStorage`.
- Вакансии есть: работодатель публикует условия, кандидат видит подходящие и откликается. Отклик — согласие показать контакты этому работодателю.
