# ФСП Талант

Обратный найм для трека ФСП на LCT-2026. Работодатель ищет категорию участников по протоколам и отправляет оффер с зарплатой. Имя и контакты открываются только после согласия кандидата.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec -u appuser backend python -m seed.generate_seed
```

Миграция выполняется при старте backend. Сайт: http://localhost (nginx). API (8010), фронтенд (3010), PostgreSQL (5432) и Redis (6379) опубликованы только на 127.0.0.1; снаружи доступен только nginx.

Публичный адрес после деплоя — `SITE_ADDRESS` из `deploy/README.md` (IP через дефисы и `.sslip.io`). Пока секрет `DEPLOY_HOST` не задан, CI стенд не обновляет.

Письма с кодами подтверждения видны в Mailpit: http://localhost:8025 (на стенде — настоящий SMTP через `MAIL_MODE=smtp` и `SMTP_*` в `.env`).

Демо-вход (пароль у всех `demo12345`, компании вымышленные):

| Кто | Email | Что показывает |
|-----|-------|----------------|
| Кандидат | fsp001@demo.talent | привязан ФСП ID, подтверждённые результаты |
| Кандидат | fsp002@demo.talent | ФСП, специализация ИБ |
| Кандидат | nofsp@demo.talent | нет истории ФСП: категория по опросу и тесту |
| Работодатель | hr@sibcode.demo | три потребности с шорт-листом, приглашения во всех статусах, отклики |

Сид `seed.generate_seed` вместе с базой создаёт активность: 40 вымышленных кандидатов прошли адаптивный тест через тот же сервис, что и API (ответы смоделированы по 3PL), у «Сибирского кода» три потребности с шорт-листами, восемь приглашений в разных статусах и шесть откликов. Фильтр «только подтверждённые тестом» сразу непустой.

### Демо за 5 минут

1. **Работодатель** `hr@sibcode.demo` → «Потребности» → «Backend на Python в платёжный сервис». Подборка упорядочена одним скором, у каждой карточки — полосы факторов и «Почему в выдаче». Отметьте трёх кандидатов «Сравнить»: факторы встанут рядом, лучший в строке выделен.
2. Там же «Какой тест получится»: доли тем из текста потребности и три примера заданий без ответа.
3. «Пригласить» на карточке: роль, вилка до вычета НДФЛ, способ связи. Кандидату приходит письмо и уведомление в колокольчике.
4. **Кандидат** `fsp001@demo.talent` → колокольчик → приглашение → «Принять». У работодателя в «Приглашениях» открываются контакты, в журнале доступа появляется запись.
5. «Тест на грейд»: выбор уровня и языка кода (Python, JavaScript, Go, Java), задания по одному. Если ответ — целое число, его вводят без вариантов. В конце — результат с темами.
6. Профиль → «Согласия» → отозвать согласие на обработку: контакты закрываются сразу (`consent_withdrawn`), через 30 дней данные стираются задачей `purge_withdrawn`. «Удалить аккаунт» стирает сразу.
7. API: http://localhost/docs (Swagger UI работает под CSP стенда).

## Аккаунты и согласия

- Регистрация обеих ролей по email с подтверждением кодом из 6 цифр или ссылкой (ТЗ 2.2 п. 4). Код хранится только как HMAC, живёт 30 минут, 5 попыток, повторная отправка не чаще раза в минуту. Есть сброс пароля.
- История ФСП для регистрации не нужна (ТЗ 2.1). ФСП ID привязывается в профиле. Демо-мок: FSP2000–FSP2099, пароль `test` (ещё не привязанные) и FSP1000–FSP1149 (уже в сиде). Вход через ФСП ID не подключён: адаптер один, сейчас это мок.
- Согласие на обработку ПДн — отдельный документ (ч. 1 ст. 9 152-ФЗ в ред. 156-ФЗ), публичная страница требует ещё одного согласия на распространение (ст. 10.1). Тексты лежат в `backend/app/legal/docs/`, в БД хранится версия и SHA-256 принятого текста; отзыв — в профиле.
- При регистрации спрашиваем «мне есть 18», а не дату рождения. После привязки ФСП дата берётся из протокола, и возраст считается по ней. Несовершеннолетний скрыт из поиска до согласия представителя.
- Контакты отдаются работодателю только при действующем согласии на обработку: после отзыва — ответ `consent_withdrawn`. Через 30 дней после отзыва имя, контакты, ФСП ID и навыки стираются (ч. 5 ст. 21), удаление аккаунта стирает сразу; анонимные результаты соревнований и журнал согласий остаются.
- О каждом шаге найма вторая сторона получает письмо и уведомление в колокольчике. В письмах нет данных другой стороны: до согласия работодатель видит только категорию.
- Все ошибки API в одном формате с машинным кодом: [docs/API_ERRORS.md](docs/API_ERRORS.md).

## Две оси профиля

Грейд не выводится из соревнований. Его подтверждает тест (см. ниже); пока теста нет, грейд берётся из самооценки или стажа и помечается как неподтверждённый. Ось «подтверждено ФСП» считается отдельно, версия `v2.0.0`:

```
p = 1 - (place - 0.5) / N                 процентиль Хазена
q = W(разряд ЕВСК) * p                    качество результата
w = 2^(-месяцы / 18) / sqrt(размер команды)
μ = (Σ w q + K μ0) / (Σ w + K)            K=2, μ0=0.30
σ = sqrt(0.04 / (Σ w + K))
ранжирование по LCB = μ - σ
```

Это апостериор нормально-нормальной модели с известной дисперсией наблюдения τ²=0.04 и приором N(0.30, τ²/K); веса w — дробные псевдонаблюдения. σ не зависит от разброса результатов, LCB = μ − 1σ (≈ 84 % односторонней уверенности). Командный результат уменьшает вес доказательства и расширяет σ, а не снижает уровень. Разряд-эквивалент — упрощённая лестница ЕВСК; МС и КМС требуют не меньше 6 участников.

## Опрос и тест на грейд

Категория = опрос (специализация, отрасль, цель: работа или стажировка) + заявленный грейд + тест (ТЗ 2.1). Специализация задаёт роль в категории и состав теста; грейд подтверждается отдельно для каждой специализации. Шестая дисциплина ФСП «программирование систем ИИ» (ЕКП 2026) учтена и связана со специализацией ML.

Тест адаптивный и устойчив к утечке:

- Задания на подсчёт операций показываются на языке, который кандидат выбрал перед тестом: Python, JavaScript, Go или Java; тест перезапускает каждую программу соответствующим компилятором.
- Описание вакансии задаёт доли тем: названные навыки подтягивают соответствующие семейства, остальное остаётся планом специализации. Примеры заданий видны работодателю до публикации, правильный ответ не отдаётся.
- Короткая практика — одно такое задание. Грейд не меняется. На анонимной карточке видно, верно ли оно решено.
- Задания по одному из **параметрических семейств** с пятью уровнями сложности (Python, SQL, JavaScript, алгоритмы, графы, сети, безопасность, ML, встраиваемые системы). Ответ вычисляется кодом; тест `test_item_families.py` перезапускает каждый фрагмент в Python, Node.js и SQLite. Статичных концептуальных вопросов не больше 30 %. LLM в рантайме не используется.
- **IRT 3PL**: угадывание 1/4, если ответ выбирают из четырёх вариантов, и 0,02, если ответ — целое число и кандидат вводит его сам (вариантов на экране нет). Апостериор на сетке, **CAT на классификацию**: задание выбирается по информации в точке порога грейда, randomesque, доли тем по плану специализации, 8–20 заданий, остановка при уверенности 90 %.
- Грейд подтверждён при P(уровень) ≥ 75 %, повышение на ступень — при P(следующий уровень) ≥ 90 %. Тест не понижает подтверждённый грейд; после повышения 90 дней ожидания; пересдача того же уровня — через 7 дней, прерванная попытка засчитывается.
- Правильный ответ не уходит на клиент до конца; ответ принимается по HMAC-токену текущего задания; время засекает сервер.
- **Мониторинг утечки**: дрейф решаемости по каждому ключу с оценкой способности без заданий того же семейства; при z ≥ 3,5 ключ уходит в карантин. Статистика открыта: `GET /api/v1/public/assessment/items`. Калибровка трудности: `python -m app.validation.calibrate`.
- Навыки с ≥ 75 % верных на ≥ 3 заданиях получают отметку «подтверждён тестом».

Проверка симуляцией с атакой утечкой: [docs/VALIDATION_ASSESSMENT.md](docs/VALIDATION_ASSESSMENT.md). На 2000 кандидатах, seed 7, дальше 0,5 от порога тест прав в 91,7 % случаев, каппа повторной сдачи 0,51. Те же люди, если все ответы выбирать из четырёх: 88,5 % и 0,42. Команда: `cd backend && python -m app.validation.assessment --n 2000 --seed 7`. CI гоняет тот же прогон на 300 кандидатах с порогами (`--check`).

## Интерфейс

Дизайн-система «Протокол» построена на [брендбуке ФСП](https://fsp-russia.ru/press/brandbook/):
- фирменные цвета `#402FFF`, `#EC1D35`, `#EDEDED`, `#C8C9CA`, `#1B1C21`;
- фирменный шрифт JetBrains Mono — для заголовков и цифр; длинный текст набран Golos Text;
- на главной — карта России с сетью региональных отделений.

Подборка выглядит как протокол соревнований: место, категория «специализация × грейд», подтверждения и скор с полосами факторов. Красный цвет только у приглашения, золото только у разрядов. Есть светлая и тёмная темы. Приглашение и текст согласия открываются нативным диалогом: фокус остаётся в окне, Escape и щелчок по фону его закрывают. Контраст текста — не ниже AA, ширина экрана — от 390 px, анимации отключаются при `prefers-reduced-motion`. Шрифты, Swagger UI и карта лежат в проекте, внешних запросов нет. Подробности, токены и таблица контраста — в [docs/DESIGN.md](docs/DESIGN.md).

## Подбор: потребности и объяснимый скор

Работодатель описывает **потребность** (специализация, грейд, обязательные и желательные навыки, отрасль, стажировка); каждое изменение — новая версия, шорт-лист помнит версию, по которой выбран кандидат, и показывает воронку. Для потребности считаются **рекомендуемые категории** «специализация × грейд».

Порядок выдачи — один **разложимый скор** (`app/services/matching.py`). Соответствие потребности (навыки 0,50, грейд 0,20, специализация 0,20, текст 0,05, отрасль 0,05) решает, попадает ли человек в список. Тест и протокол ФСП только переставляют кандидатов внутри одной сотой этого соответствия. Нет истории ФСП — эта ось выбрасывается и не штрафует. В разборе карточки есть строка «Лучше N % кандидатов категории» по вероятности теста внутри «специализация × грейд». Навык весит по силе доказательства (тест 1,0, цитата из резюме 0,75, заявление 0,55). В карточке — полосы факторов и строки «плюс / минус / инфо». Фильтры «с ФСП / без ФСП» и «стажировка».

Качество проверено на синтетическом наборе со скрытой правдой против случайного порядка и базовой линии по ключевым словам, с абляциями: [docs/VALIDATION_MATCHING.md](docs/VALIDATION_MATCHING.md) (`python -m app.validation.matching`, есть `--export` и `--import` для разметки жюри).

## Поиск

Жёсткие фильтры в SQL: профиль открыт, несовершеннолетний только с согласием законного представителя (сам участник этот флаг не меняет), роль, грейд, дисциплина, минимальный разряд. Дальше лексический ранг (`ts_rank` + триграммы) и опционально векторный поиск. Слияние — RRF с K=60. Итоговый порядок: покрытие навыков, грейд подтверждён тестом, RRF, лучший LCB (при выбранной дисциплине — LCB именно в ней). В RRF отдельным рангом входит лучший θ теста. Фильтр `assessed_only` оставляет только подтверждённые грейды. `total` в ответе — размер ранжируемого пула (≤ 1000), флаг `pool_capped` говорит, что пул обрезан. Карточка без имени (псевдонимная): статус соревнования, год и корзина процентиля, без названия события и точного места.

Плотные эмбеддинги выключены (`EMBEDDINGS_MODE=off`), пока не подключён `sentence-transformers`. Разбор резюме работает правилами: навыки из словаря и поля (имя, телефон, Telegram, стаж, заявленный грейд, специализация), у каждого дословная цитата. Поля переносятся в профиль кнопкой «Применить»; входная почта аккаунта из резюме не меняется. GigaChat добавляет навыки только если цитата дословно есть в тексте и задан `GIGACHAT_CREDENTIALS`.

## Удостоверения

W3C VC Data Model 2.0, Data Integrity `eddsa-jcs-2022`. Издатель — платформа, не ФСП: она подтверждает, что результат получен из системы ФСП. Проверка: `GET /api/v1/public/issuer` и `POST /api/v1/public/credentials/verify`.

## Правовые границы прототипа

Контакты видны только после принятия оффера; событие пишется в `consent_logs`, просмотр — в `access_logs`. В `consent_logs` также пишутся отказ от оффера и каждое переключение `is_visible` / `public_profile`. Ответ на оффер и отзыв сериализованы блокировкой строки, активный оффер на пару «работодатель–кандидат» ровно один (уникальный индекс). Именная страница и лидерборд недоступны несовершеннолетним. ИИ только предлагает навыки и разбирает запрос, решение остаётся за человеком.

## Ограничения прототипа

- Все данные синтетические: `RealFSPAdapter` ждёт спецификацию API ФСП.
- Нет потока согласия законного представителя; в демо несовершеннолетние в поиск не попадают.
- Канонизация VC не проверена на тест-векторах W3C; нет статуса отзыва и ротации ключа.
- Трудность заданий откалибрована только на симуляции; на реальных ответах нужна калибровка (`app.validation.calibrate`).
- Rate limit есть на вход, поиск, старт теста и приглашения (50 в сутки). Если Redis недоступен, вход, регистрация и письма отвечают 503; поиск и приглашения пропускают запрос, чтобы демо не вставало. Refresh-эндпоинт без отзыва, фронтенд его не использует; токены хранятся в `localStorage`.
- Вакансии есть: работодатель публикует и правит условия, кандидат видит подходящие и откликается. Статус отклика меняется в кабинете работодателя. Отклик — согласие показать контакты этому работодателю. Карточка компании — название, ИНН, сайт и описание. PDF-резюме разбирается и не сохраняется; PDF профиля скачивается из кабинета и с публичной страницы.
