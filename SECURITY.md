# Политика безопасности

## Поддерживаемые версии

Исправления выходят только в ветку `main`. Отдельных веток сопровождения нет: актуальная версия API — `1.1.0`, методика балла ФСП — `v4.2.0`.

| Версия | Исправления безопасности |
|---|---|
| `main` | да |
| более ранние коммиты | нет, обновитесь до `main` |

## Как сообщить об уязвимости

Не публикуйте детали в открытых Issues, обсуждениях и пул-реквестах.

1. Откройте вкладку **Security** репозитория и нажмите **Report a vulnerability** ([частное сообщение GitHub](https://github.com/KonkovDV/fsp-talent/security/advisories/new)). Сообщение увидят только владельцы репозитория.
2. Опишите, что затронуто (маршрут API, экран, контейнер, файл), как воспроизвести, какой результат ожидался и какой получен, и чем это грозит: утечка персональных данных, обход согласия, подмена грейда, выполнение кода.
3. Если есть доказательство, приложите минимальный запрос или скрипт. Настоящие персональные данные не прикладывайте.

Мы подтвердим получение, договоримся о сроке исправления и укажем вас в описании исправления, если вы не против.

## Что входит в область

- API backend (`backend/app`), включая проверки прав, политики строк PostgreSQL и обработку согласий по 152-ФЗ.
- Интерфейс (`frontend/src`): раскрытие контактов, хранение токенов, CSP.
- Песочница кода (`sandbox/`): выход в сеть, побег из контейнера, обход лимитов.
- Удостоверения W3C VC и SD-JWT: подделка подписи, обход проверки отзыва.
- Продуктивная сборка (`deploy/`): Caddy, резервные копии, роли базы.

## Что не считается уязвимостью

- Опубликованные демо-аккаунты и пароль `demo12345`: это часть демо-режима (`DEMO_MODE=true`), смена пароля и удаление этих аккаунтов закрыты нарочно.
- Возможности, которые работают только в демо-режиме и описаны в [README](README.md#демо-режим-и-промышленный-контур): пробный тест, гостевой вход, код подтверждения на экране, страница-имитация провайдера ФСП ID.
- Синтетические демо-данные: люди и компании в них вымышлены.
- Отчёты сканеров без сценария атаки.

## Как устроена защита

- Модель угроз: атака, защита и где это измерено — [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md).
- Сверка с OWASP ASVS, сессии, шифрование, роли базы — [docs/SOLUTION.md, гл. 10](docs/SOLUTION.md#10-безопасность-и-152-фз).
- 152-ФЗ: согласия, отзыв, удаление, несовершеннолетние — [docs/COMPLIANCE.md](docs/COMPLIANCE.md).
- В CI на каждый пуш: поиск секретов (gitleaks), `pip-audit`, `npm audit`, SBOM CycloneDX с подписью Sigstore cosign, обход всех маршрутов API с чужими идентификаторами (`backend/tests/smoke_api.py`).
